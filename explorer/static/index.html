What are Per-Layer Embeddings?

Per-Layer Embeddings (PLE), introduced with Google's Gemma 3n, give every transformer layer its own small embedding of the current token, in addition to the usual input embedding. They live in one big table E of shape [V, L·p]: row t holds L slices of size p, one per layer. Because the table is only ever indexed (never multiplied), it can sit in slow memory (CPU RAM or flash) and only the rows for the current tokens need to be fetched, which is why PLE parameters are "cheap". Each layer's input mixes the token's slice with a projection of the ordinary embedding x₀:

u_l = ( E[t]_l · √p · mask_l  +  RMSNorm(W_ctx · x₀ · d^-½)_l ) / √2

After its attention and MLP sublayers, block l computes a gate from the residual stream h, multiplies it element-wise by u_l, and projects back:

h ← h + RMSNorm( W_proj · ( gelu(W_gate · h) ⊙ u_l ) )

The gate decides how much of the token's per-layer information to read in this context, and the slice decides what is read. This explorer shows the slices themselves (Token, Map, Stats), how strongly the model gates them while reading real text (Analyze), and what happens to the loss when they are removed (Ablate PLE sets mask_l = 0) or compared against a baseline model trained without PLE (Compare).

Reading the views

  • Norms: slices start at norm ≈ 0.02·p; rows that never appear in training stay there, so the norm is a proxy for "how trained" a token is.
  • Neighbours: tokens with similar slices in a layer are treated alike by that layer's PLE path. Early layers often group by spelling/surface form, later ones by role.
  • Gate magnitude: mean |gelu(Wgateh)|. High = the layer is reading a lot of this token's slice at this position.
  • Contribution ratio: size of the PLE update relative to the residual stream; it is how loudly PLE "speaks" in each layer.
  • Δloss: ablated − normal loss. Red tokens got harder to predict without PLE, so the model relies on PLE for them.
